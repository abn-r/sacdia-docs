## 2. Backend — NestJS + Prisma

**Ubicacion**: `/sacdia-backend`

### Modulos principales
```
src/
├── auth/                 # Endpoints canonicos /auth/* (consume Better Auth)
├── better-auth/          # BetterAuthModule self-hosted (Wave 3)
├── users/                # Usuarios, progreso de clases
├── catalogs/             # Catalogos (honores, medicinas, etc.)
├── clubs/                # Gestion de clubes
├── classes/              # Clases progresivas
├── honors/               # Honores y categorias
├── activities/           # Actividades de club
├── finances/             # Finanzas
├── camporees/            # Camporees
├── certifications/       # Certificaciones Guias Mayores
├── folders/              # Carpetas de evidencias
├── inventory/            # Inventario
├── rbac/                 # Control de acceso basado en roles
├── admin/                # Endpoints de administracion
├── common/               # Guards, decorators, filtros, interceptores
├── investiture/          # Validacion de investiduras
├── notifications/        # Firebase FCM + realtime invalidation (BullMQ)
├── evidence-review/      # Validacion de evidencias (7 endpoints)
├── analytics/            # SLA dashboard y metricas operacionales
├── resources/            # Categorias + recursos (presigned R2)
├── materiales/           # Catalogo, ordenes, comprobantes, inventario
├── audit-logs/           # Trazabilidad de cambios
└── prisma/               # Migraciones, seeds, esquema
```

### Stack
- **Runtime**: NestJS 11 + TypeScript 6 + Node 22 LTS
- **ORM**: Prisma 7 → PostgreSQL 16 (Neon, 3 branches)
- **Auth**: **Better Auth** self-hosted + JWT **HS256** firmado con `BETTER_AUTH_SECRET`
- **Cache / Queue**: Redis (cache-aside + BullMQ + throttler distribuido)
- **Storage**: Cloudflare R2 (presigned URLs)
- **Push / Realtime**: Firebase Cloud Messaging (data-only silent multicast)
- **Prefijo API**: `/api/v1/*`

### Convenciones
- Respuesta admin: `{ status, data }`
- Guards: `JwtAuthGuard`, `GlobalRolesGuard`, `OwnerOrAdminGuard`
- Async/await para todas las operaciones
- Validacion de entrada via decoradores de NestJS

## 3. Admin — Next.js 16 + shadcn/ui

**Ubicacion**: `/sacdia-admin`

### Estructura
```
app/
├── (auth)/               # Rutas publicas (login, register)
├── (dashboard)/          # Dashboard protegido
│   ├── clubs/
│   ├── users/
│   ├── activities/
│   ├── finances/
│   └── [otros]
├── api/                  # API Routes de Next.js
└── layout.tsx

components/
├── ui/                   # shadcn/ui componentes base
├── clubs/                # Componentes especificos del feature
├── activities/
├── finances/
└── [otros features]/

lib/
├── auth/                 # Better Auth client + cookies httpOnly
├── api/                  # apiRequest wrapper + TanStack Query keys
├── i18n/                 # next-intl config + helpers
└── generic-catalogs-i18n/ # PhaseECatalogCrudPage helpers
```

### Stack
- **Framework**: Next.js 16 (App Router + `proxy.ts` reemplaza al viejo `middleware.ts`)
- **UI**: shadcn/ui (registry `new-york`) + Radix UI + Tailwind CSS v4
- **Icons**: lucide-react
- **Forms**: React Hook Form + Zod + aria-invalid Form primitive
- **Auth**: Better Auth (cookie `ACCESS_TOKEN_COOKIE` httpOnly; JWT HS256 backend-signed)
- **Server state**: **TanStack Query v5** (no SWR)
- **i18n**: next-intl 4 + 4 idiomas (es/en/fr/pt-BR)
- **Testing**: Vitest + MSW + Testing Library
- **Design System**: Ver `sacdia-admin/DESIGN-SYSTEM.md` (paleta Ember, Geist sans)

### Convenciones
- Server Components por defecto; `'use client'` solo donde necesario
- CRUD dialogs: crear/editar → Dialog modal
- Delete → AlertDialog confirmacion
- Semantic colors en Tailwind (no hardcoded: `bg-primary/10`, `text-muted-foreground`)

## 4. App Movil — Flutter + Clean Architecture

**Ubicacion**: `/sacdia-app`

### Estructura
```
lib/
├── core/
│   ├── constants/        # URLs, claves, constantes globales
│   ├── theme/            # Tema Material + colores
│   └── utils/            # Funciones utilitarias
├── data/
│   ├── models/           # Mapeos JSON ↔ Dart
│   ├── repositories/     # Implementacion de repositorios
│   └── datasources/      # Clientes HTTP (Dio)
├── domain/
│   ├── entities/         # Entidades del negocio (puros)
│   ├── repositories/     # Contratos abstractos
│   └── usecases/         # Logica de negocio
└── presentation/
    ├── screens/          # Pantallas principales
    ├── widgets/          # Componentes reutilizables
    └── providers/        # Riverpod state management
```

### Stack
- **Framework**: Flutter 3.27+ / Dart 3.6+
- **Architecture**: Clean Architecture (data / domain / presentation)
- **State**: Riverpod (DI + state) + `flutter_hooks` NO se usa
- **HTTP**: Dio + interceptors (auth + retry)
- **Storage**: `flutter_secure_storage` (tokens) + `shared_preferences` (settings)
- **Auth**: Better Auth (JWT HS256 emitido por SACDIA)
- **Realtime**: FCM silent push → `RealtimeInvalidationHandler` invalida cache
- **Observabilidad**: `sentry_flutter` + `secure_application` (PII scrub)
- **i18n**: `easy_localization`
- **Errors**: `dartz` (Either) en domain layer

### Convenciones
- DI via Riverpod providers
- JWT en `flutter_secure_storage` (no Hive — Hive no esta en el pubspec)
- Async/await + `dartz Either` en domain
- HugeIcons typedef obligatorio para iconos (no IconData)

## 6. Nombrado — Convenciones Globales

### TypeScript (Backend + Admin)
- **Variables/funciones**: `camelCase`
- **Clases/interfaces**: `PascalCase`
- **Enums**: `UPPER_CASE`
- **Archivos**: `kebab-case` (`.controller.ts`, `.service.ts`)

### SQL/Prisma
- **Tablas/columnas**: `snake_case`
- **PKs**: `id` (siempre)
- **FKs**: `[tabla]_id`
- **Timestamps**: `created_at`, `updated_at`

### Flutter/Dart
- **Classes**: `PascalCase`
- **Variables/functions**: `camelCase`
- **Files**: `snake_case.dart`
- **Folders**: `snake_case`

### Git
- **Commits**: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`
- **Ramas**: `feature/`, `fix/`, `docs/`
- **PRs**: Descripcion clara en body; no en titulo

## 7. Encontrar cosas rapido

### Buscar endpoint
Ir a `/dev/api` → referencia de endpoints (Ctrl+F por modulo o metodo)

### Buscar modelo de datos
Ir a `/dev/base-de-datos/schema-reference` → referencia humana  
O `sacdia-backend/prisma/schema.prisma` → autoridad

### Buscar especificacion de feature
Ir a `docs/features/{nombre-dominio}.md`  
Ejemplo: `docs/features/actividades.md`

### Buscar componente de admin
Ir a `sacdia-admin/components/[feature]/` o `app/(dashboard)/[feature]/`

### Buscar pantalla de app
Ir a `sacdia-app/lib/presentation/screens/` o `lib/domain/usecases/`

### Buscar estandar de codigo
Ir a `/dev/estandares/coding-standards`

### Entender decisiones arquitectonicas
Ir a `docs/canon/decisiones-clave.md` o `docs/canon/arquitectura-sacdia.md`

## 10. Validacion de Estructura

Verificar que estas en la estructura correcta:

- Backend tiene `/src/[modulo]/` con `.module.ts`, `.service.ts`, `.controller.ts`
- Admin tiene `/app/(dashboard)/[feature]/` con `page.tsx` + componentes en `/components`
- App tiene `/lib/domain/`, `/lib/data/`, `/lib/presentation/` claros
- Docs tiene `/canon/`, `/features/`, `/api/`, `/steering/`, `/database/` como autoridad
- Commits siguen `feat:`, `fix:`, `docs:` (sin "Co-Authored-By")
