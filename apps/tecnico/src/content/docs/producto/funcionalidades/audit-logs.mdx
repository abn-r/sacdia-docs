## Propósito

`audit_logs` es la traza persistente de acciones de dominio y mutaciones HTTP. Sirve para investigación operativa; no implementa event sourcing ni convierte cada lectura en un evento auditable.

Cada registro identifica la entidad, actor, acción, resultado, origen, correlación y momento. Los eventos de dominio pueden incluir `changes`; los eventos HTTP conservan únicamente contexto seguro de la solicitud.

## Consulta global

| Método | Ruta | Autorización |
| --- | --- | --- |
| GET | `GET /api/v1/admin/audit-logs` | JWT, rol global `super-admin`, `audit:read` y recurso global |
| GET | `GET /api/v1/admin/audit-logs/:id` | JWT, rol global `super-admin`, `audit:read` y recurso global |

Ambas rutas declaran `@Audit({ skip: true })`: consultar la traza no genera una nueva fila de la misma traza. No tienen alcance territorial.

### Lista paginada

La lista es descendente por `audit_log_id` (más reciente primero) y devuelve:

```ts
type AuditLogPage = {
  items: Array<{
    audit_log_id: string;
    entity_type: string;
    entity_id: string;
    action: string;
    result: string;
    source: string;
    summary: string | null;
    club_id: number | null;
    correlation_id: string | null;
    actor: { user_id: string; name: string | null; paternal_last_name: string | null } | null;
    created_at: string;
  }>;
  next_cursor: string | null;
};
```

Filtros de backend:

| Query | Restricción |
| --- | --- |
| `entity_type` | cadena de hasta 50 caracteres |
| `actor_user_id` | UUID del actor |
| `action` | cadena de hasta 64 caracteres |
| `result` | `succeeded` o `failed` |
| `source` | `http` o `service` |
| `from` / `to` | fecha ISO; límites inclusivos |
| `club_id` | entero positivo |
| `correlation_id` | UUID de correlación |
| `limit` | entero de 1 a 100; predeterminado 50 |
| `cursor` | `audit_log_id` decimal recibido en `next_cursor` |

La lista omite `changes` y `request_context`. El detalle por `:id` incluye ambos campos cuando existen; `:id` debe ser un decimal válido.

## Historial de club

`GET /api/v1/clubs/:clubId/history` es una vista acotada al club: requiere JWT, `clubs:read` y autorización sobre el recurso club. También ordena en forma descendente y usa `limit`/`cursor` con `next_cursor`; no es sustituto de la consulta global.

## Interceptor HTTP de auditoría

`HttpAuditInterceptor` se registra globalmente mediante `APP_INTERCEPTOR` en `AuditLogsModule`.

- Persiste mutaciones `POST/PUT/PATCH/DELETE` como eventos con `source: "http"`; las lecturas no se persisten.
- Excluye `health`, `auth/refresh`, handlers con `@Audit({ skip: true })` y solicitudes que ya emitieron un evento de dominio o crítico más rico.
- Registra éxito o fallo en `result` y conserva contexto técnico seguro (método, ruta saneada, estado, duración, IP y agente de usuario truncado).
- Nunca persiste el body. `changes` queda reservado para eventos explícitos de dominio, evitando registrar credenciales o datos sensibles.
- La escritura es **best-effort**: una falla al registrar no modifica la respuesta de la operación original.

## Límites verificables

- La traza no garantiza una estructura uniforme de `changes` entre dominios.
- La presencia de un evento depende de que la ruta sea una mutación interceptable o de que el flujo de dominio emita un evento explícito.
- `request_context` del detalle no representa ni reconstruye el body de la solicitud.
